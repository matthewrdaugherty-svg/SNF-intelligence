# DECISION LOG

Format: D-### | date | decision | why | who | status

D-001 | 2026-10-26 | Use DuckDB (single file `db/snf.duckdb`) as the data environment; Excel is an *export* from it, not the source of truth. | Files are 100–180 MB; pivot/filter in Excel of 800k-row long tables is impractical; DuckDB is free, portable, and any future app queries it directly. | Orchestrator | active
D-002 | 2026-10-26 | Primary key is `ccn` as 6-char text with leading zeros preserved. | CMS CCNs like "015019" lose meaning as integers; state code is in the first two digits. | Data Engineer | active
D-003 | 2026-10-26 | Long measure files are pivoted wide into one row per facility, carrying each value's footnote as a sibling column. | Matt asked for a filterable/pivotable sheet; one-row-per-facility is the only shape that works for that. Footnotes must travel with values (Operating Rule 1.3). | Orchestrator | active
D-004 | 2026-10-26 | SNF QRP "comparative performance" text values ("Better/No Different/Worse than the National Rate") are kept as categorical text columns, not encoded as numbers. | They are CMS's statistical determination, not a score; encoding would invite misuse. | Quality Expert | active
D-005 | 2026-10-26 | Any composite/ranking score we build is prefixed `x_` and documented with its full formula in the workbook; no `x_` score ships until the Quality Expert and Validator sign off. | Avoid passing off our construct as a CMS rating. | Orchestrator | active
D-006 | 2026-10-26 | Hospital→SNF discharge flows are declared OUT OF SCOPE for the Care Compare-only build and tracked as a separate data acquisition workstream. | None of the 18 files contain a hospital identifier (T-007). Pretending otherwise would violate the zero-hallucination rule. | Orchestrator | active — pending Industry Maven findings
D-007 | 2026-10-26 | Swing-bed SNF data (764 hospital CCNs) is loaded as its own table and NOT merged into the nursing-home master. | Different provider type and universe; merging would corrupt facility counts. | Data Engineer | active
D-008 | 2026-10-26 | Agent/model tiering: extraction & web research on mid-tier models; design, methodology, and independent validation on top-tier. The builder of an artifact never validates it. | Matt's cost-discipline request + independence of verification. | Orchestrator | active
D-009 | 2026-10-26 | Every numeric/date cast in the pipeline asserts "non-blank raw values == non-null typed values"; the build fails if any value is lost. | A heuristic cast silently nulled 4 date columns on the first run (caught by inspection, not by the pipeline). Never again. | Lessons-Learned Mgr | active
D-010 | 2026-10-26 | For "deficiencies cited" use Survey Summary / Health Citations counts; use Provider Info "Rating Cycle" counts only when describing what the star rating used. | T-009: the two differ for 449 facilities, partly due to IDR/IIDR exclusions. | Quality Expert (provisional) | active — 162 unexplained cases open
D-011 | 2026-10-26 | Workbook v2 ships with all 16 Validation-Report-01 fixes: lossless-cast guard on every cast with declared sentinels; ownership dates parsed; a '— footnote' column beside every suppressible value; unique headers; units on VBP (fraction 0–1) vs % elsewhere; numeric/date typing on survey-summary fields; complaint measures (12-month complaint deficiencies, complaint inspections with citations); ownership partnership/individual-operator columns + data-available flag; MDS 409/415/452/454/480 added; explicit severity IN-list; 12-month window derived from processing date and asserted against CMS Collection_Intervals; complete lineage; VBP withhold explained; x_vbp_net_part_a_payment_change_pct added (derived, labelled). | Validator findings. | Orchestrator | active
D-012 | 2026-10-26 | Product scope per Matt: INTERNAL use for now (not commercial); focus on Medicare and Medicaid populations. | Matt's answer. Keeps MedPAR/HSCRC research-use options open; revisit if it becomes commercial. | Matt | active
D-013 | 2026-10-26 | Hospital→SNF flows: build a MODELED catchment layer now (free CMS files: Post-Acute Care PUF, Hospital Service Area File, Hospital Spending by Claim), designed so a hospital's real discharge records can be dropped in later. Concretely: one `discharge_flows` table with a fixed schema (hospital_ccn, snf_ccn, period, n_discharges, source = 'modeled' | 'hospital_reported', method, loaded_at); every analysis reads from that table and shows the source label; real data replaces modeled rows for the hospitals that provide it, modeled rows remain for the rest. | Matt: hospitals may share discharge data; "make it easy to plug real data in later". | Matt / Orchestrator | active
D-014 | 2026-10-26 | Web app v1 architecture: static site (Vite + React + TypeScript), DuckDB running in the browser (duckdb-wasm 1.32.0 pinned) over Arrow IPC exports of the validated database; no server, no secrets, no runtime downloads from third parties except the map basemap (OpenFreeMap) and the optional place lookup (OpenStreetMap Nominatim). | Public data only in v1 → cheapest, simplest hosting; Parquet was rejected because duckdb-wasm fetches its Parquet reader from extensions.duckdb.org at runtime (blocked in restricted networks and an external dependency). | Orchestrator | active
D-015 | 2026-10-26 | Hosting: Vercel, as a static deploy of app/ (root directory `app`, build `npm run build`, output `dist`), connected to the GitHub repo so every push deploys. v1 has no password (public CMS data; Matt wants to share by link). Password protection/SSO requires Vercel Pro — only with Matt's explicit OK. The moment hospital data moves beyond aggregated counts (i.e. PHI), hosting moves to a HIPAA-eligible provider with a BAA and the sensitive layer goes behind an authenticated API. | Matt: "use Vercel", "share with other people"; standing rule: ask before any spend. | Matt / Orchestrator | active
D-016 | 2026-10-26 | App data files (app/public/data/*.arrow, ~42 MB) are committed to git so Vercel can build from the repo; refreshed only when CMS data is refreshed (quarterly). | Simplicity over Git LFS/CDN for an internal tool. Revisit if history bloats. | Orchestrator | active
